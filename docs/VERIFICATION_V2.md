# V2 verification report

## Что проверялось

Работа выполнена по GitHub Issue #1 в отдельной ветке `codex/hideki-ai-agent-v2`, поверх V1. Issue прочитан через его HTML-страницу; GitHub API в этой среде возвращал 403. Источник реальной проверки предоставлен владельцем: `https://www.instagram.com/alexandro_hideki/`.

Автоматические проверки используют временные SQLite и явно обозначенные тестовые HTTP/AI ответы/DOM. Они доказывают выполнение инструментов, сохранность и guards, **не** доступ к реальному Instagram или качество генерации конкретной внешней модели.

Покрытие: intent parsing и защита исходного handle от подмены моделью; cursor pagination и дедупликация; доступные profile/posts; отсутствие выдуманных публикаций/citations; московские evidence, shipping/hashtag rejection; три оффера и независимая оценка; память/контрольные точки; STOP/RESUME/истёкший lease; follow-up commands; cross-task duplicate outreach; bulk approval; unsupported channel; остановка задачи вопреки старому CRM approval; blacklist до запроса профиля; шифрование V1 credentials; desktop/mobile console и V1 CRM; браузерный DOM-коннектор с явно тестовыми страницами.

## Реальная проверка @alexandro_hideki — BLOCKED, не PASS

1. Реальный HTTPS-запрос к `https://www.instagram.com/alexandro_hideki/` завершился `CONNECT tunnel failed, response 403`, HTTP 000. Это блокировка сетевого прокси облачной среды **до ответа Instagram**, не сообщение Instagram о приватности аккаунта.
2. В текущей машине нет операторской авторизованной Instagram-сессии; пользовательские cookie/пароль не запрашивались и не извлекались.
3. FreeLLMAPI по локальному адресу не запущен, внешние профильные credentials не предоставлены.
4. Запущен настоящий `agent:verify -- @alexandro_hideki` с отдельной SQLite и без фикстур. Задача `93c2643d-e7d6-439f-bfa9-a7b087122fda` разобрана ограниченным явно обозначенным fallback parser; инструмент `getFollowers` перевёл её в blocked с причиной «Браузерная сессия не подключена». Обнаружено 0, подготовлено 0. Код выхода 2. Это корректная диагностика, не успешная Instagram-интеграция.
5. В черновик cloud network settings добавлены `instagram.com`, `www.instagram.com`, `i.instagram.com`, `*.cdninstagram.com`, `*.fbcdn.net`. Сохранённый черновик не применяет runtime-сеть и не публикует среду; требуется сохранение/публикация оператором. Даже после сети нужна его авторизация.

Успешный vertical slice «реальный подписчик → реальная публикация → grounded draft» **остаётся неподтверждённым в этой среде**. Для него необходим реальный разрешённый источник/сессия и доступный AI. Тестовые данные не подставлялись вместо недоступных реальных.

## Чек-лист проверки на Mac

1. `npm ci`, `npx playwright install chromium`; создать `.env.local`, настроить AI. В CRM → Settings проверить сохранённое соединение реальным запросом.
2. Остановить worker; `npm run instagram:login`; вручную войти, включая 2FA, нажать Enter, дождаться закрытия процесса.
3. Либо запустить UI и worker и создать задачу для `@alexandro_hideki`, либо (при остановленном worker) выполнить `npm run agent:verify -- @alexandro_hideki`.
4. Проверить, что `getFollowers` завершился completed и вернул реальный известный handle из списка исходного аккаунта. Сверить его вручную с Instagram. «Сессия сохранена» сама по себе не подтверждает этот шаг.
5. Проверить bio/публикации, открывая source URL. Если сайт не отдал дату/публикацию — убедиться, что интерфейс это не придумал.
6. Проверить Moscow evidence и цитату. Доставка/хештег/поездка не должны считаться местоположением бизнеса. Unknown-кандидаты не должны попасть в prepared.
7. Проверить три варианта, выбор, сообщения и отсутствие выдуманных достижений/клиентских фактов. Отредактировать в CRM при необходимости.
8. Нажать STOP, перезапустить worker, RESUME: этапы должны продолжиться, handle не дублироваться. Повторная задача не создаёт повторную отправку тому же контакту.
9. Проверить «почему», «убери агентства», «ещё», «без вопросов»; убедиться, что редактирование сбрасывает approval.
10. Для первого реального теста оставить глобальную очередь приостановленной. Проверить ручное копирование и профиль. Автоматическую отправку тестировать отдельно только с доступным разрешённым provider/получателем; фиктивный sent недопустим.

Если Instagram предлагает challenge, блокирует automation, скрывает followers или меняет DOM, прекратить текущий источник и показать ошибку. Пройти разрешённую ручную проверку либо использовать API-поставщика с нужным доступом; не обходить ограничение.
