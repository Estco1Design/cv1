# HIDEKI AI AGENT V2

Исполняемый агент для исследования доступных подписчиков Instagram и подготовки предложений fashion-фотографа Александра Хидеки. Главная страница — **Agent Chat / Task Console**. CRM V1 сохранена по `/crm`.

Реализация [Issue #1](https://github.com/Estco1Design/cv1/issues/1). Новый код находится в ветке `codex/hideki-ai-agent-v2`.

> Реальные данные требуют доступного источника и авторизации. Приложение не подставляет фиктивных подписчиков и не выдаёт тестовые вызовы за подключённый Instagram. В текущей облачной проверке Instagram заблокирован сетевым прокси (`CONNECT 403`), авторизованной сессии и запущенного FreeLLMAPI нет. Успешное получение реального подписчика и генерация оффера из его данных здесь **не подтверждены**. Для проверки на вашем Mac предусмотрен полный процесс ниже.

## Запуск на Mac

Нужны Node.js **24**, npm и браузер Chromium. Если сборка `better-sqlite3` требует компилятор: `xcode-select --install`.

```sh
git clone -b codex/hideki-ai-agent-v2 https://github.com/Estco1Design/cv1.git
cd cv1
npm ci
cp -n .env.example .env.local
npx playwright install chromium
```

Если V1 уже установлена, сохраните `.env.local` и `data/`, выполните `git fetch origin`, перейдите на новую ветку и выполните `npm ci`. Данные V1 остаются в той же SQLite; миграция V2 добавляет таблицы задач.

В `.env.local` задайте `APP_PASSWORD` (имя входа `hideki`) и `SETTINGS_ENCRYPTION_KEY` — результат `openssl rand -hex 32`. Ключи не публикуйте и не отправляйте в чат. Для FreeLLMAPI:

```dotenv
AI_BASE_URL=http://127.0.0.1:31415/v1
AI_MODEL=auto:coding
INSTAGRAM_SOURCE=browser
INSTAGRAM_SESSION_DIR=./data/instagram-session
# На Mac можно наблюдать работу браузера; на headless VPS оставьте true.
INSTAGRAM_BROWSER_HEADLESS=false
```

FreeLLMAPI запускается **отдельно** на вашем Mac. В CRM → Settings можно указать другой OpenAI-compatible endpoint, API key, модели анализа/генерации/оценки/vision и выполнить Test saved connection. Поддерживаются Chat Completions и Responses. Без AI допускается только ограниченный явно обозначенный разбор стандартной русской команды; анализ и генерация не симулируются.

### 1. Войти в Instagram вручную

Остановите worker и любые процессы `agent:verify`, если они запущены.

```sh
npm run instagram:login
```

Откроется **выделенный браузерный профиль приложения**. Самостоятельно войдите в Instagram, пройдите 2FA/проверки в браузере, затем нажмите Enter в терминале. Пароль и коды нельзя вводить в терминал или интерфейс приложения. Команда проверит наличие авторизованной сессии и закроет браузер. После этого профиль можно открыть worker.

Сессия хранится только в `data/instagram-session/` с ограниченными правами доступа; каталог исключён из Git. Не используйте основной профиль Chrome и не переносите cookie в чат. Одновременно этот профиль может использовать **один** worker / login / verifier.

### 2. Запустить приложение и worker

Терминал 1 из папки `cv1`:

```sh
npm run dev
```

Терминал 2 из той же папки:

```sh
npm run worker
```

Откройте локально `http://127.0.0.1:3000`. Введите:

> Проанализируй подписчиков @alexandro_hideki, найди 30 потенциальных клиентов из Москвы для fashion-съёмок Александра Хидеки, изучи последние публикации, подготовь по три персональных оффера, выбери лучшие и подготовь отправку в Direct.

Выберите **Авторизованный браузер** и нажмите START. Журнал во вкладке «Инструменты и прогресс» показывает реальные вызовы и ошибки. Результаты содержат username, происхождение от исходного аккаунта, московские свидетельства, публикации со ссылками/датами, эвристический балл и выбранный оффер. Недоступные сведения обозначаются явно.

Команды продолжения:

- `почему выбрал @username?` — объяснение по сохранённым данным;
- `убери агентства` — исключение и отмена их неотправленных сообщений;
- `обработай ещё 20` — увеличение цели и продолжение с курсора;
- `переделай офферы без вопросов` — новые версии для ещё не отправленных контактов, сброс старого одобрения.

Для другого исходного аккаунта или города создайте новую задачу. Произвольные команды вне поддерживаемых действий не выполняются молча. PAUSE/STOP сохраняют память и курсор; RESUME продолжает с контрольного шага. Уже начатую внешнюю отправку отозвать нельзя.

### 3. Проверка одного реального результата из CLI

Это **альтернатива** работающему worker. Сначала остановите worker; login должен быть завершён, AI доступен.

```sh
npm run agent:verify -- @alexandro_hideki
```

Команда создаёт настоящую постоянную задачу с целью найти одного подходящего московского клиента, вызывает реальные инструменты и выводит происхождение, свидетельства, публикации и выбранный черновик. Она ничего не отправляет. Если доступ не позволяет получить подписчиков либо подходящий клиент не найден в пределах лимитов, выводит точный статус; фикстуры не используются. Результат/ошибку также можно открыть в веб-интерфейсе, если DATABASE_PATH совпадает.

Коды завершения: `0` — задача завершена с подходящим черновиком; `2` — внешняя зависимость/доступ блокируют шаг; `3` — доступный список/лимит проверок не дал подходящего результата; `1` — ошибка запуска; `4` — достигнут предел одного проверочного запуска, задача сохранена. Не считайте `2`/`3` доказательством успешного подключения.

## Как действительно получаются данные

Два production-источника, без обязательного CSV:

1. **BrowserInstagramSource** — Playwright persistent context с операторской сессией. Открывает профиль, ссылку followers, читает доступный DOM списка, прокручивает его и сохраняет уже встреченные username в cursor. Читает header профиля и до трёх доступных последних публикаций с caption/URL/датой/изображением, если сайт их предоставил. Это конкретный исполняемый коннектор, а не интерфейс для будущего парсера.
2. **HTTP source** — подключение к авторизованному поставщику, действительно поддерживающему подписчиков. Сохраняет opaque pagination cursor и использует существующий V1 profile endpoint. Контракт в [AGENT_V2.md](docs/AGENT_V2.md).

Браузерный список может быть ограничен платформой; порядок меняется, полнота всех подписчиков не гарантируется. Большие списки могут превысить ограниченный проход прокрутки. Закрытый/недоступный список, login wall, challenge, изменение DOM и ограничения частоты отражаются в ошибке инструмента. CAPTCHA/2FA не обходятся, закрытые данные не подменяются догадками. Официальный Instagram API не даёт общего доступа к подписчикам любого аккаунта.

На VPS сессия должна находиться на машине worker. Локальный FreeLLMAPI на Mac не доступен VPS по `127.0.0.1`: нужен защищённый маршрут либо облачный AI endpoint. Обычные `HTTPS_PROXY`/`HTTP_PROXY` учитываются браузером; при необходимости задайте серверный `INSTAGRAM_BROWSER_PROXY`. Прокси не отменяет разрешения платформы.

## Память, инструменты и отправка

`agent_tasks`, `agent_steps`, `agent_chat_messages`, `agent_candidates` добавляются миграцией к базе V1. Каждый кандидат хранит исходный аккаунт, cursor происхождения, профиль, публикации, оценку, географические свидетельства, варианты офферов, выбор и message ID. Worker выполняет один инструмент за итерацию; lease/token и транзакционный checkpoint защищают от дублирования после сбоя. При аварийном завершении running lease восстанавливается через 5 минут; явный RESUME сбрасывает старый lease сразу. Read-only/AI-шаг после прерывания может выполняться повторно; внешняя отправка не повторяется автоматически.

Реестр: `getFollowers`, `fetchProfile`, `fetchRecentPosts`, `analyzeCandidate`, `draftOffers`, `selectOffer`, `queueMessage`, `sendViaProvider`. LLM разбирает задачу и анализирует данные; детерминированный оркестратор выбирает разрешённые шаги, проверяет схемы, пределы и полномочия. Native tool-calling модели не требуется.

Локация не берётся из догадки AI: нужны реально существующие источники и подходящее упоминание целевого города. Доставка, хештег или несуществующая цитата не подтверждают Москву. Неизвестный город исключается из целевого списка. Коммерческое соответствие и скоринг остаются эвристикой, не вероятностью сделки. Без мультимодальной модели указывается текстовый режим; изображения не объявляются просмотренными.

Черновики требуют отдельной/массовой проверки. Одобрение **не означает отправку**. Глобальная очередь включается отдельно в CRM → Outreach, затем провайдер проверяет разрешение для конкретного получателя. Без такого метода — копирование и открытие профиля для ручной отправки. Браузерный коннектор не рассылает Direct. Blacklist, opt-out, интервалы, stop switch и постоянный idempotency key сохранены. Один контакт не получает новое сообщение из другой задачи; редактирование/переписывание ещё не отправленного собственного сообщения сохраняет ID и сбрасывает одобрение.

## Проверки и документация

```sh
npm run typecheck
npm test
npm run build
npm run smoke
npm run test:e2e
```

Выполняйте build/typecheck и E2E последовательно: Next генерирует служебные типы. На Linux с системным Chromium: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e`. Тестовые HTTP/AI server и DOM-фикстуры явно обозначены и не подключаются к production. Smoke проверяет реальные процессы Next/worker, сохранность после перезапуска и честную блокировку V2 при отсутствии сессии. CI запускает проверки без внешних аккаунтов.

## Структура

```text
app/page.tsx               Agent Chat / Task Console
app/crm/page.tsx           сохранённый интерфейс CRM V1
app/api/[...path]/route.ts API задач и CRM
lib/agent/schema.ts       типы/схемы намерения и источника
lib/agent/migration.ts    постоянные задачи, шаги и кандидаты
lib/agent/intent.ts       LLM parsing и ограниченный явный fallback
lib/agent/browser-source.ts  авторизованный DOM-коннектор
lib/agent/sources.ts      HTTP/browser registry
lib/agent/tools.ts        grounded evidence и типизированные инструменты
lib/agent/runner.ts       исполняемый оркестратор и checkpoints
lib/agent/queue.ts        перенос выбранного оффера в безопасную очередь
lib/agent/service.ts      память чата, управление и bulk approval
scripts/worker.ts         V1 + V2 worker
scripts/instagram-login.ts  ручной вход в выделенный браузер
scripts/agent-verify.ts   реальный CLI vertical check
```

Для 24×7: `npm ci && npm run build`, отдельные supervised Next (`npm start`) и worker (`npm run worker`), одинаковые WorkingDirectory/DATABASE_PATH, постоянный диск, APP_PASSWORD, HTTPS reverse proxy, резервная копия SQLite и отдельное хранение encryption key/браузерной сессии. Один процесс может владеть браузерным профилем. PostgreSQL и многопользовательский RBAC остаются за пределами этой версии.
